1. 📖 Présentation du Projet

1.1 Vue d'ensemble

Foo-Link est une plateforme web collaborative permettant aux passionnés de cuisine de partager, découvrir et commenter des recettes culinaires du monde entier. Le projet vise à créer une communauté active de gourmets créatifs autour du partage de savoir-faire culinaire.

1.2 Objectifs

  • Créer une plateforme intuitive et moderne pour le partage de recettes
  • Faciliter la découverte de nouvelles recettes via un système de recherche et de catégorisation
  • Encourager l'interaction entre utilisateurs (likes, commentaires)
  • Offrir un tableau de bord complet pour la gestion des recettes
  • Mettre en avant les contributeurs les plus actifs de la communauté

1.3 Public cible

  • Amateurs de cuisine souhaitant partager leurs créations
  • Débutants à la recherche d'inspiration et de recettes faciles
  • Professionnels voulant partager leur expertise
  • Communauté culinaire cherchant un espace d'échange

3. 🏗️ Architecture Technique

3.1 Architecture MVC

Le projet suit le pattern MVC (Modèle-Vue-Contrôleur) pour une séparation claire des responsabilités :

┌─────────────────────────────────────────────────────────────┐
│                        CLIENT (Navigateur)                   │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP Request
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                    CONTRÔLEURS (Controllers/)                │
│  • RecetteController.php    • ConnexionController.php      │
│  • CommentaireController.php • inscriptionController.php   │
│  • CategorieController.php   • ProfilController.php        │
│  • LikeController.php        • StatController.php          │
└───────────────┬─────────────────────┬───────────────────────┘
                │                     │
                │ Logique Métier      │ Récupération Données
                ▼                     ▼
    ┌──────────────────┐    ┌──────────────────────┐
    │   VUES (Views/)  │    │   MODÈLES (Models/)  │
    │  • recettes.php  │    │  • Recette.php       │
    │  • recette.php   │    │  • User.php          │
    │  • connexion.php │    │  • Commentaire.php   │
    │  • dashboard/    │    │  • Like.php          │
    │  • partials/     │    │  • Categorie.php     │
    └──────────────────┘    │  • Database.php      │
                            └──────────┬───────────┘
                                       │
                                       │ PDO
                                       ▼
                            ┌──────────────────────┐
                            │   BASE DE DONNÉES    │
                            │   MySQL (foo_link)   │
                            └──────────────────────┘

Modèles (Models/)

  • Database.php : Classe parent gérant la connexion PDO
  • Recette.php : Gestion CRUD des recettes, pagination, recherche
  • User.php : Authentification, gestion des utilisateurs
  • Commentaire.php : Gestion des commentaires
  • Like.php : Système de likes/unlikes
  • Categorie.php : Gestion des catégories

Contrôleurs (Controllers/)

  • RecetteController.php : Actions CRUD sur les recettes
  • ConnexionController.php : Login/Logout
  • inscriptionController.php : Création de compte
  • CommentaireController.php : Gestion des commentaires
  • LikeController.php : Actions like/unlike
  • CategorieController.php : CRUD catégories
  • ProfilController.php : Mise à jour profil
  • StatController.php : Statistiques

Vues (Views/)

  • Pages publiques : index.php, recettes.php, recette.php, connexion.php, inscription.php
  • Dashboard : index.php, recettes.php, commentaires.php, categories.php, profil.php
  • Partials : navbar.php, footer.php, head.php, dashboard_sidebar.php

Helpers & Services

  • csrf.php : Génération et validation des tokens CSRF
  • StatService.php : Calcul des statistiques

7. ⚙️ Configuration

7.1 Configuration de la Base de Données

Le fichier de configuration se trouve dans config/config.php :

<?php
$host = 'localhost';
$db = 'foo_link';
$user = 'root';
$pass = '';  // Mot de passe vide par défaut avec XAMPP
$charset = 'utf8';

$dsn = "mysql:host=$host;dbname=$db;charset=$charset";
$opt = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
];

try {
    $cnx = new PDO($dsn, $user, $pass, $opt);
} catch(PDOException $e) {
    die('Connection failed: '. $e->getMessage());
}
?>
⚠️ Sécurité : En production, changez le mot de passe de la base de données et mettez à jour ce fichier.

7.2 Configuration PHP

Vérifiez le fichier php.ini (accessible via XAMPP Control Panel → Config) :

; Taille maximale des uploads (pour les futures images)
upload_max_filesize = 10M
post_max_size = 10M

; Affichage des erreurs (développement uniquement)
display_errors = On
error_reporting = E_ALL

; Sessions
session.cookie_httponly = 1
session.use_strict_mode = 1

7.3 Configuration Apache

Le fichier .htaccess (si présent) devrait contenir :

RewriteEngine On
RewriteBase /foo-link/

# Redirection des erreurs
ErrorDocument 404 /foo-link/index.php

# Protection des fichiers sensibles
<FilesMatch "^(config\.php|database_schema\.sql)$">
    Order allow,deny
    Deny from all
</FilesMatch>

9. 🔒 Sécurité

9.1 Mesures de Sécurité Implémentées

Protection contre les Injections SQL

  • ✅ Utilisation exclusive de requêtes préparées PDO
  • ✅ Paramètres bindés avec types explicites
  • ✅ Pas de concaténation directe de variables dans les requêtes
Exemple : 
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = ?");
$stmt->execute([$email]);

Protection contre les Attaques XSS

  • ✅ Utilisation de htmlspecialchars() sur toutes les sorties
  • ✅ Validation des données en entrée
  • ✅ Échappement des attributs HTML

Protection CSRF

  • ✅ Génération de tokens CSRF uniques par session
  • ✅ Validation des tokens sur tous les formulaires POST
  • ✅ Helper dédié : helpers/csrf.php

Gestion des Mots de Passe

  • ✅ Hachage avec password_hash() (bcrypt)
  • ✅ Vérification avec password_verify()
  • ✅ Pas de stockage en clair
  • ✅ Politique de mot de passe minimum (6 caractères)

Gestion des Sessions

  • ✅ Sessions PHP natives sécurisées
  • ✅ Vérification de l'authentification avant actions sensibles
  • ✅ Destruction complète à la déconnexion

9.2 Recommandations pour la Production

⚠️ IMPORTANT : Avant de déployer en production, appliquez ces modifications critiques :
  1. Désactiver l'affichage des erreurs 
    display_errors = Off
error_reporting = E_ALL
log_errors = On
  2. Changer les credentials de la base de données 
    $user = 'nouveau_user';
$pass = 'mot_de_passe_fort';
  3. Activer HTTPS
    • Obtenir un certificat SSL
    • Forcer la redirection HTTPS
    • Utiliser session.cookie_secure = 1
  4. Renforcer la politique de mots de passe
    • Minimum 8-12 caractères
    • Exiger majuscules, minuscules, chiffres, symboles
    • Implémenter un système de récupération sécurisé
  5. Implémenter un système de limitation de taux (Rate Limiting)
    • Limiter les tentatives de connexion
    • Protéger contre les attaques par force brute
  6. Ajouter des headers de sécurité 
    header("X-Frame-Options: DENY");
header("X-Content-Type-Options: nosniff");
header("X-XSS-Protection: 1; mode=block");

12. ⚠️ Problèmes Connus et Limitations

Note : Cette section répertorie les fonctionnalités non implémentées ou non fonctionnelles actuellement dans le projet.

12.1 Fonctionnalités Non Implémentées

🔴 Critiques

Fonctionnalité État Description du Problème Impact
Upload d'images Non implémenté Les recettes ne peuvent pas avoir d'images. Une image fixe (pie-8396728_1280.jpg) est utilisée pour toutes les recettes. Limite l'attractivité visuelle et l'expérience utilisateur
Gestion des permissions Non fonctionnel N'importe quel utilisateur connecté peut modifier ou supprimer n'importe quelle recette, même s'il n'en est pas l'auteur. Sécurité compromise, risque de vandalisme
Protection CSRF complète Partiel Les contrôleurs suivants n'ont pas de validation CSRF :
  • LikeController.php
  • CommentaireController.php
  • RecetteController.php
  • CategorieController.php
 Vulnérabilité aux attaques CSRF
Transactions base de données Non implémenté La suppression d'une recette ne supprime pas les likes et commentaires associés, créant des enregistrements orphelins. Intégrité des données compromise

🟠 Importantes

Fonctionnalité État Description du Problème
Système de notifications Non fonctionnel Le bouton de notification (🔔) dans la navbar est présent mais n'a aucune fonctionnalité backend associée.
Filtrage par catégories Non fonctionnel Les liens de catégories sur la page d'accueil (Entrées, Plats, Desserts, Boissons) utilisent des paramètres GET qui ne sont pas gérés par le backend.
Récupération de mot de passe Non implémenté Aucun système de "Mot de passe oublié" n'est disponible. Les utilisateurs ne peuvent pas récupérer leur compte.
Vérification d'email Non implémenté Les utilisateurs peuvent s'inscrire avec n'importe quel email sans vérification. Risque de faux comptes.
Pagination des commentaires Non implémenté Tous les commentaires sont chargés d'un coup, sans limite. Risque de problèmes de performance.
Système de rating (étoiles) Non implémenté Seul le système de likes existe. Pas de notation détaillée par étoiles (1-5).
Validation stricte des entrées Faible
  • Pas de limite de longueur pour titre/description
  • Pas de sanitization HTML complète
  • Validation email basique uniquement

🟡 Mineures

Fonctionnalité État Description
Avatars utilisateur Non fonctionnel Les utilisateurs ne peuvent pas uploader d'avatar. Un placeholder est utilisé.
Messages de confirmation Incomplet Pas de messages de succès/erreur après la plupart des actions (ajout, modification, suppression).
Recherche avancée Limitée La recherche fonctionne uniquement sur titre et description. Pas de filtres par catégorie, auteur, date, etc.
Statistiques dashboard Basiques Les statistiques sont très simples. Pas de graphiques, d'évolution temporelle ou d'analytics avancées.
Système de tags Non implémenté Impossible d'ajouter des tags (ex: "végétarien", "sans gluten") aux recettes.
Favoris/Bookmarks Non implémenté Les utilisateurs ne peuvent pas sauvegarder leurs recettes préférées.

12.2 Problèmes Techniques

Code et Architecture

  • Code dupliqué
    • Connexion PDO répétée dans plusieurs fichiers (index.php, etc.)
    • Gestion de $root dupliquée dans chaque fichier
    • 3 versions de la page d'accueil : index.php, index_old.php, index_modern.php
  • Gestion des erreurs incohérente
    • display_errors activé dans inscriptionController.php (dangereux en production)
    • Messages d'erreur affichés avec echo au lieu de templates
    • Pas de logging centralisé
  • Redirections problématiques
    • CommentaireController redirige vers un chemin incorrect après suppression
    • Redirections relatives non cohérentes
  • Requêtes SQL non optimisées
    • Potentiels problèmes N+1 dans certaines pages
    • Pas d'index sur toutes les clés étrangères

Sécurité

  • Mot de passe base de données vide en config.php
  • Pas de protection rate-limiting contre les attaques par force brute
  • Pas de régénération d'ID de session après login
  • Pas de timeout de session
  • Headers de sécurité manquants (X-Frame-Options, CSP, etc.)

Performance

  • Aucun système de cache (Redis, Memcached)
  • Pas de lazy loading des images
  • Pas de compression des assets (CSS/JS non minifiés)
  • Pas de CDN pour les ressources statiques

UX/UI

  • Design inconsistant
    • Page d'accueil avec design moderne glassmorphism
    • Pages apropos.php et contact.php avec ancien design
  • Responsive incomplet
    • Certains éléments dashboard mal adaptés sur mobile
    • Menu mobile pourrait être amélioré
  • Accessibilité limitée
    • Attributs ARIA manquants sur plusieurs éléments
    • Contraste des couleurs parfois insuffisant
    • Navigation au clavier incomplete
